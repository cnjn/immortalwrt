# SR1010 固件槽位与版本头

这份文档记录原厂系统怎么管理两个固件槽位，以及我们的镜像和 `zte-fwslot` 为什么这样做。
每条结论后面标了来源：**反编译**（读原厂二进制得出）、**实测**（在设备上测得）、
**推断**（由前两者推出，没有直接验证）。

## 1. 闪存布局

| 区域 | 地址 | 说明 |
| --- | --- | --- |
| 槽 0 | `0x600000`–`0x2f00000` | 41 MiB，一个完整的固件 |
| 槽 1 | `0x2f00000`–`0x5800000` | 41 MiB，另一个固件 |
| `Plugin` | `0x5800000` 起，40 MiB | 原厂插件，ImmortalWrt 的覆盖层放在其中的 `.owrt` 目录 |

擦除块 128 KiB（`0x20000`）。

槽内的内容按顺序写在**好块**里（跳过坏块）：

```text
原厂 U-Boot (0x180000) | 内核魔数 (32 B) + AES-128-ECB 加密的 FIT 内核 | 填充到块边界 | rootfs
                                                          ...  body 之后的下一个好块：512 字节版本头
```

- 内核用 AES-128-ECB 加密，密钥 `SR101038c09ffb98`；原厂 rootfs 另用 `SR1010V102020030` 加密的 JFFS2，
  我们的镜像里 rootfs 是明文 squashfs（U-Boot 只对 rootfs 区域算 CRC，不解析它）。
- 版本头的位置取决于 body 的大小和坏块数，所以**每个镜像、每个槽里都不一样**，不能写死。

## 2. 版本头（512 字节）

所有 CRC 都是标准 CRC-32（zlib 的那个）。

| 偏移 | 内容 |
| --- | --- |
| `0x10` | 版本字符串，32 字节（原厂是 `V1.0.0.2B7.8000`，我们是 `ImmortalWrt 25.12.1`） |
| `0x30` | body 总大小 |
| `0x34` / `0x38` / `0x3c` | 内核大小 / 在升级包里的文件偏移 / CRC |
| `0x40` / `0x44` / `0x48` | rootfs 大小 / 在升级包里的文件偏移 / CRC |
| `0x6c` | 产品名（`ZXSLC SR1010`），52 字节 |
| `0x8c` | 非 0 表示同时升级 bootloader；我们的包保持 0 |
| `0x98` | U-Boot 的 CRC |
| `0xa4` | **CRC1**，覆盖 `[0:0xa4]` |
| `0xa8` | 构建时间，16 字节 |
| `0xb8` | 原厂 `switch` 要求这里为 0（日志里叫 "version integrality"） |
| `0xf4` | 内层魔数 `33333333 66666666 99999999 cccccccc` |
| `0x1e0`–`0x1ec` | 两个槽的起止地址：`0x600000`、`0x2f00000`、`0x2f00000`、`0x5800000` |
| `0x1f0` | 这份头部所在槽的起始地址 |
| `0x1f4` | **序号**（serial） |
| `0x1f8` | 新版本标志，刷写后为 1 |
| `0x1fc` | **CRC2**，覆盖 `[0:0x1fc]`，包含序号 |

升级包里的文件偏移（`0x38`、`0x44`）指的是包文件内的位置；换算成槽内偏移时，
内核固定在 body 偏移 `0x180020`，rootfs 在内核加上两者文件偏移之差处。

## 3. U-Boot 怎么选槽（反编译）

- 每隔 128 KiB 扫描整片闪存，找内层魔数，并校验 **CRC1**，得到两个槽各自的序号。
- 槽 0 的序号小于槽 1，或槽 0 的序号为 0，就启动槽 1；否则启动槽 0。**序号相等时启动槽 0。**
- 只看 CRC1，**不看 CRC2**。
- 选中的槽如果起不来（比如内核超过原厂 U-Boot 限制，报 `malloc tmp_kernel failed`），
  **不会**自动换成另一个槽（实测）。
- U-Boot 自己的刷写函数把序号改成 `最大序号 + 1`，但**不重算 CRC2**。所以用 U-Boot 的
  `upgrade` 命令装进去的槽，CRC2 是过期的（推断，没有单独验证）。

## 4. 原厂正常刷写（`fw_flashing` 的 `WriteVersion`，反编译 + 实测）

1. `SetVersionHeader`：从升级包取头部，序号写 `最大序号 + 1`，`0x1f0` 写目标槽起始，
   `0x1f8` 写 1，**重算 CRC2**。
2. 先擦掉备份头部所在的块，再擦掉整个目标槽。
3. 逐块写 body，坏块跳过；然后在下一个好块写 512 字节头部。
4. `Checkheader` 回读头部与写入内容比较。

**实测：** 经原厂网页装入的 ImmortalWrt，头部的 CRC1 和 CRC2 都正确，和我们打包的头部只在
`0x1f0`、`0x1f4`、`0x1f8`、`0x1fc` 四处不同。这条路径是好的。

## 5. 原厂 `fw_flashing -v switch` 是坏的（反编译 + 实测）

`CspSwitchVersion` 的流程：

1. 从 `/proc/zte/verinfo/versionstates` 取 `backverheaderaddr` 和 `maxversionum`；
2. 读出那里的 512 字节，检查 CRC2 和 `0xb8`；
3. 把序号改成 `maxversionum + 1`，重算 CRC2；
4. 用 `CspUserMtdWrite` 把 512 字节**就地写回，之前没有擦除**；
5. 打印成功，睡几秒后重启。

问题有三处：

- **不擦除。** NAND 只能把位从 1 变成 0，落进闪存的是新旧字节**按位与**的结果。
  序号取 `28 & 30 = 28`，不会变大，所以重启后不会切换；CRC2 也被按位与，从此对不上。
- **错误处理反了。** `CspUserMtdWrite` 大多数失败返回 `1`，调用方却把 `>= 0` 当成成功，
  只有返回负数才重试。
- **写完不回读。** 和 `WriteVersion` 不同，这里没有 `Checkheader`。

所以它会打印 `Version switch success`，实际上把头部写坏。

**实测**（设备在 2B5，ImmortalWrt 序号 28，2B5 序号 29，工具要写的新序号是 30）。
先算出两种结果的字节，实验后与之比较：

| `0x1f4` 到 `0x1ff` | |
| --- | --- |
| 实验前 | `1c 00 00 00 01 00 00 00 e4 9f 9e bd` |
| 按位与（预测） | `1c 00 00 00 01 00 00 00 80 98 9a bd` |
| 正常擦除后写入（预测） | `1e 00 00 00 01 00 00 00 99 98 bb ff` |
| **实测** | `1c 00 00 00 01 00 00 00 80 98 9a bd` |

实测与"按位与"的预测逐字节一致。此后每次调用都在日志里报
`[U_fw_flashing][Error] ... version header crc failed`。

U-Boot 只看 CRC1，所以被写坏的槽按理仍然能启动，只是序号太小不会被选中（推断，没有试过启动这个槽）。

**结论：** 不要在原厂系统里用 `fw_flashing -v switch`。要回到 ImmortalWrt，在原厂网页里再刷一次镜像，
它会擦掉整个槽。反方向用 `zte-fwslot switch`，它先校验目标槽，再擦除头部所在的块并整块写入。

## 6. `/proc/zte/verinfo/versionstates`

- **是启动时的快照**，写闪存之后不会更新（实测）。
- `fw_flashing` 只读它的前 1023 字节（反编译）；正常内容约 800 字节，在范围内。
- 与切换相关的键：`curverBootStartPhyAddr`（运行中槽的起始地址）、`curverheaderaddr`、
  `curverSerialNumber`、`backverheaderaddr`、`backverSerialNumber`、`maxversionum`。
- 一次重新刷写之后，头部位置会变，**之前记下的地址全部过期**。

## 7. 在设备上排查

- 日志：串口控制台上能看到，也可以用 `logcat` 查看，关键字 `U_fw_flashing`。
- 读头部（要有 `dd` 和 `hexdump`；原厂 2B7 的 busybox 没有 `dd`）：

  ```sh
  hdr() { dd if=/dev/mtd0 bs=512 skip=$(( $1 / 512 )) count=1 2>/dev/null | hexdump -C; }
  hdr 0x55a0000
  ```

- 原厂工具成功后会很快重启。要在重启前读出结果，可以放到后台，睡眠期间读取，再杀掉它：

  ```sh
  fw_flashing -v switch & P=$!
  sleep 2; hdr 0x55a0000; kill $P
  ```

  这只用于排查；**不要对一个有用的槽这样做**，它会把头部写坏。
- 在 ImmortalWrt 里：`zte-fwslot info [-j]` 显示两个槽的序号、版本和下次启动的槽。
